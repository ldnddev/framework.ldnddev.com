Finding Component Breakdown

Overview

The dd-finding component renders a list of audit findings, where each item combines a severity badge (embedding dd-badge), a title, and optional evidence and fix details. An accent stripe reinforces the severity for quick visual scanning.

This component is ideal for accessibility, SEO, and security audit reports where issues need to be listed with clear priority. In WordPress, configure it via a repeater of findings with severity, title, evidence, and fix fields. In Drupal, use a Paragraph type with a select for severity and text areas for evidence and fix.

Basic Usage

Wrap the findings in a dd-finding list, using <ol> when the order communicates priority or <ul> when it does not. Each dd-finding__item holds a severity dd-badge, a title heading, and optional evidence and fix blocks. Apply the matching stripe modifier per item.

CSS Modifiers (from _dd_finding.scss)

The SCSS file defines the item layout, accent stripe, and spacing for evidence and fix blocks, with stripe modifiers driven by design tokens. Key modifiers include:

  • -critical: Error-toned accent stripe for critical findings.
  • -warning: Warning-toned accent stripe for warnings.
  • -info: Info-toned accent stripe for informational notes.
  • -pass: Success-toned accent stripe for passing checks.

Accessibility and Best Practices

Findings use real list semantics with <ol> or <ul> so assistive technology announces the count and position (WCAG 1.3.1 Info and Relationships). Severity is stated by the badge word, not the stripe colour alone (WCAG 1.4.1 Use of Colour). The finding title heading level continues the page outline without skipping levels (WCAG 1.3.1), and any inline links inside evidence or fix keep their underline and a visible focus indicator.
